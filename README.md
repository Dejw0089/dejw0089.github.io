# yusuke-iw.github.io

Yusuke Iwasaki のプロフィールサイト。下までスクロールすると「無駄コーナー」（クソゲー・バカアプリの詰め合わせ）がある。遊ぶと音源がたまり、「グルーヴ機」で重ねて鳴らせる。

公開URL: https://yusuke-iw.github.io/

## 構成

```
index.html            トップ（アプリ一覧・グルーヴ機・セーブコード）
core/core.js          共通基盤：保存・解放判定・解放演出・セーブコード
core/core.css         共通スタイル（ヘッダー・トースト）
data/apps.json        アプリ一覧
data/unlocks.json     音源の解放ルール（全員共通）
apps/<id>/index.html  各アプリ
sounds/*.wav          120BPM の音源ループ（2小節 = 4秒）
sounds/180/*.wav      180BPM・DnB の音源ループ（4小節 = 5.33秒）
sounds/400/*.wav      400BPM・speedcore の音源ループ（4小節 = 2.4秒）
sounds/1280/*.wav     1280BPM・extratone の音源ループ（4小節 = 3.0秒）
sounds/120/*.wav      120BPM の追加分（あとから足した6つ）
tools/make_sounds.py  音源ループの合成スクリプト（numpy だけで動く）
```

## データの持ち方

- 進捗はブラウザの localStorage（キー `fuzake-box-v1`）に保存。サーバーなし。
- 形は `{ v: 1, stats: { <アプリid>: { <項目>: 数値 } }, unlocked: [<音源id>], drops: [<到達点id>], since }`。
- 音源と解放ルールは `data/unlocks.json`：
  - `sounds` … 音源の一覧。`bpm` はその音源が属するテンポ（120 / 180 / 400 / 1280）。名前は何の楽器か分からないものにする。
  - `drops` … 各ゲームの到達点。「`app` の `stat` が `gte` 以上」になるたびに、まだ持っていない音源がランダムで1つ出る（どのゲームからどのテンポの音源が出るかは決まっていない）。`drops` の数と `sounds` の数を揃えておけば全部集まる。
  - 受け取った到達点は `drops: [<id>]` として保存する。
- 消えたとき・端末の引っ越し用に、トップの「セーブ」からセーブコード（`FZ1.` で始まる文字列）を出し入れできる。

## アプリの増やし方

1. `apps/<新しいid>/index.html` を作る。中で `/core/core.css` と `/core/core.js` を読み込む。
2. 遊んだ実績を報告する：
   - 累計に足す … `FZ.add('<id>', '<項目>', 1)`
   - 最高記録 … `FZ.max('<id>', '<項目>', 値)`
3. `data/apps.json` に1行足す（トップに出る）。
4. `data/unlocks.json` の `drops` にそのゲームの到達点を足す。同じ数だけ `sounds` に音源も足す（`sounds/` にファイルを置き、
   `bpm` を付け、そのテンポのセットと同じ長さちょうどのループにする。WAV推奨。MP3は継ぎ目に隙間が出やすい）。

## テンポ（グルーヴ機）

- 音源はテンポごとのセットに分かれている：120 ／ 180（DnB）／ 400（speedcore）／ 1280（extratone）。画面上はBPMの数字だけ出す。
- グルーヴ機の上のタブで切り替える。鳴らせるのは常に1セットだけで、切り替えると前のテンポは止めてから新しいテンポを鳴らす。
- 選んだテンポは `stats.top.bpm` に保存。
- 同時に鳴らせる音源は `data/unlocks.json` の `maxOn`（6つ）まで。テンポごとに選択を覚えている。
- おすすめの組み合わせは `data/unlocks.json` の `presets`（各テンポ3つ）。全部持っていないおすすめは「🔒 あとN」で選べない。最初は「全部そろっている最初のおすすめ」が選ばれる。
- 再生中はBPMに合わせて枠の中が光る（ランプ・ゆっくり回る光・ときどき「確定」）。てんかんへの配慮で、光の強弱は毎秒2回まで（速いテンポは2・4・16拍に1回にまとめる）、パッと点滅させずふわっと変化させ、光るのは枠の中だけ。OSの「視差効果を減らす」がオンなら最初からOFF、「演出」ボタンで切り替え（ブラウザに `fz-fx` で保存）。

## アプリのページ

- 上部に、そのゲームの到達点（条件・進み具合・出た音源名）を小さく並べる。`core.js` が `/apps/<id>/` を見て自動で出すので、アプリ側は何もしなくていい。
- 画面がスクロールしないよう、中身は帯の高さぶん下げる（`body.fz-has-drops` の `padding-top`）。全画面キャンバスのアプリは帯を上に重ねるだけにする（納豆を参照）。
- トップのアプリ一覧は6個ずつのページ（‹ ›・点・横スワイプでめくる）。アプリから戻ると、そのアプリのあるページを開く。
- アプリからトップに戻ると、箱が開いていれば「無駄コーナー」の見出しから表示する。
- 音源は `python3 tools/make_sounds.py` で全部作り直せる（120 の6つは乱数の順番ごと固定なので、作り直しても同じ音になる）。

解放判定・「音源ゲット！」の演出・保存は core.js が自動でやるので、アプリ側は報告するだけでよい。

## キャッシュ対策

GitHub Pages はファイルを約10分キャッシュするので、core や data を変えたら `core/core.js` の `V` と各HTMLの `?v=` を同じ数字で上げる。

## 英語・日本語

- デフォルトは英語。右上の `EN / JA` で切り替え、選択はブラウザに保存（キー `fuzake-box-lang`。セーブコードには含めない）。
- JSONの文言は `{ "en": "...", "ja": "..." }` で書く（`FZ.t(値)` が今の言語を取り出す。ただの文字列ならそのまま）。
- ページの固定文言は `const T = { en: {...}, ja: {...} }` に書き、要素に `data-i18n="キー"`（改行入りは `data-i18n-html`）を付けて `FZ.apply(T)` を呼ぶ。切り替えボタンは `FZ.langToggle(親要素)`。

## ローカルで動かす

パスがルート基準（`/core/...`）なので、ファイルを直接開くのではなくリポジトリ直下でサーバーを立てる：

```
python3 -m http.server 8000
# → http://localhost:8000/
```

## テスト（TDDで運用する）

```
npm install      # 初回だけ
npm test         # 全部
npm run test:watch
```

- Jest ＋ jsdom。`tests/helpers/page.js` の `openPage('/apps/hanko/', {...})` で、リポジトリのページをそのままブラウザ代わりに開く（ビルドなし）。
  fetch・AudioContext・時計（`page.clock.ms`）・`confirm()`（既定で false。アプリ内ブラウザで実際にそうなる）などは差し替えてある。
- `tests/data.test.js` … データとファイルの整合性（音源の長さ・BPM・到達点の数・キャッシュ用バージョンなど）
- `tests/core.test.js` … 保存・ドロップ・獲得演出・セーブコード・言語・アプリページの帯
- `tests/top.test.js` … トップ（プロフィール・箱・グルーヴ機・演出・セーブ）
- `tests/apps.test.js` … 各ゲーム
- 進め方：**先に失敗するテストを書く → 実装して通す → 整える**。直したバグにも、再発を防ぐテストを1つ足す。
- push と PR で GitHub Actions が `npm test` を回す（`.github/workflows/test.yml`）。
