# yusuke-iw.github.io

Yusuke Iwasaki のプロフィールサイト（GitHub Pages）。

上は真面目なプロフィール。下までスクロールすると「無駄コーナー」がある。中身はクソゲー・バカゲー18本の詰め合わせで、遊ぶと音源がたまり、「グルーヴ機」で重ねて鳴らせる。ビルドなしの素の HTML / CSS / JS。

公開URL: https://yusuke-iw.github.io/

## 構成

```
index.html              トップ（プロフィール・無駄コーナーの箱・アプリ一覧・グルーヴ機・セーブ）
core/core.js            共通基盤：保存・音源のドロップ・獲得演出・アプリページの到達点の帯・セーブコード・言語
core/core.css           共通スタイル（ヘッダー・言語切り替え・獲得演出・到達点の帯）
data/profile.json       プロフィール（日英）
data/apps.json          ゲーム一覧（18本）
data/unlocks.json       音源・到達点・おすすめ・同時に鳴らせる数（全員共通）
apps/<id>/index.html    各ゲーム
sounds/*.wav            120BPM の最初の6つ
sounds/120|180|400|1280/*.wav   各テンポの音源ループ
tools/make_sounds.py    音源ループの合成スクリプト（numpy だけで動く）
tests/                  Jest のテスト（下の「テスト」）
icon.svg                favicon（紺の「YI」モノグラム）
manifest.webmanifest    ホーム画面に追加したときの名前・色
CLAUDE.md               作業ルール（TDD など）
```

## 音源の手に入り方

- 各ゲームに「到達点」がある（元の6本は6つ、あとの12本は4つ、計84）。到達点を満たすたびに、**まだ持っていない音源が全テンポの中からランダムで1つ**出る。到達点の数と音源の数（84）は同じなので、全部遊べば全部そろう。
- 到達点は「同じ数字のもっと上」ではなく、遊び方のバリエーションにする。例：
  - 回数・記録（10回押す、30秒なにもしない など）
  - 連続で間違える（相槌を3回連続で間違える、3回連続で猫に引っかかれる、USBが4回連続で逆 など）
  - 変な遊び方（つぶれたプチプチを押す、おじさんを取る、何も溜めずにドアノブを触る、カップ麺を1分以上放置 など）
- 音源が出ると、ゲーム画面の真ん中に「音源ゲット！」のカードと紙吹雪が出て、その音が1回鳴る（タップか4秒で閉じる。複数なら順番に）。
  - 全部持っているときに到達点を満たした場合は、到達点だけ達成済みになり、カードは出ない。
  - トップの「全部解放する」（ズル）でもカードは出ない。
- 各ゲームのページ上部に、そのゲームの到達点（条件・進み具合・出た音源名）を1行で並べる。入りきらない分は帯の中だけ横にスクロールし、ページ自体はスクロールさせない。`core.js` が `/apps/<id>/` を見て自動で出す。

## グルーヴ機

- 音源はテンポごとのセット：120（24個）／ 180・DnB（20個）／ 400・speedcore（20個）／ 1280・extratone（20個）。画面上は BPM の数字だけ出す。
- 上のタブで切り替える。鳴らせるのは常に1セットだけで、切り替えると前のテンポは止めてから鳴らし直す（読み込み中に連打しても混ざらない）。
- 同時に鳴らせるのは `maxOn`（6つ）まで。7つ目は断る。選択はテンポごとに覚えている。
- おすすめの組み合わせは各テンポ6つ（計24）。全部持っていないおすすめは「🔒 あとN」で選べない。最初は「全部そろっている最初のおすすめ」が選ばれる。どのおすすめにもベースが入り、そのテンポの全音源がどこかのおすすめに登場する。
- 各テンポの25%以上はベース（`bass: true`）。
- 再生中は BPM に合わせて枠の中が光る（ランプ・ゆっくり回る光）。光るたびに **1/128 で FEVER**（光る8回ぶん、枠と背景が虹色になり「★ FEVER ★」）。
  - てんかんへの配慮：光の強弱は毎秒2回まで（速いテンポは2・4・16拍に1回にまとめる）、パッと点滅させずふわっと変化、光るのは枠の中だけ。
  - OS の「視差効果を減らす」がオンなら最初から OFF。「演出」ボタンで切り替え（ブラウザに `fz-fx` で保存）。

## トップページ

- 「無駄の詰め合わせ」の箱をタップで開け閉めする。開閉の状態は覚えている。
- アプリ一覧は6個ずつのページ（‹ ›・点・横スワイプ）。スマホは2列×3段。
- ゲームから戻ると、箱が開いていれば「無駄コーナー」の見出しまで自動でスクロールし、そのゲームのあるページを開く。
- タイトルやフッターに、ふざけた名前は出さない（ページのタイトルは「Yusuke Iwasaki」、各ゲームは「<ゲーム名> | Yusuke Iwasaki」）。

## データの持ち方

- 進捗はブラウザの localStorage（キー `fuzake-box-v1`。**変えると訪問者の進捗が消えるので変えない**）。サーバーなし。
- 形は `{ v: 1, stats: { <アプリid>: { <項目>: 数値 } }, unlocked: [<音源id>], drops: [<到達点id>], dropSounds: { <到達点id>: <音源id> }, since }`。
- `data/unlocks.json`：
  - `maxOn` … 同時に鳴らせる数（6）
  - `sounds` … `{ id, bpm, file, name: {en, ja}, bass? }`。名前は何の楽器か分からないものにする。音源を差し替えるときは **id を変えない**（手に入れた人の分が消えないように）。
  - `drops` … `{ id, app, stat, gte, label: {en, ja} }`。「`app` の `stat` が `gte` 以上」で達成。`label` はゲームのページに出す条件。
  - `presets` … `{ id, bpm, name: {en, ja}, sounds: [<音源id>] }`
- セーブコード（`FZ1.` で始まる文字列）で、端末の引っ越しや消えたときの復元ができる。
- 「全部消す」は `confirm()` を使わず、2回押しで確定する（アプリ内ブラウザでは `confirm()` が黙って false を返すことがあるため）。

## ゲームの増やし方

1. `apps/<新しいid>/index.html` を作る（既存のゲームをひな形にする）。`/core/core.css` と `/core/core.js` を `?v=` 付きで読み込み、favicon のリンクも付ける。
2. 遊んだ実績を報告する：
   - 累計に足す … `FZ.add('<id>', '<項目>', 1)`
   - 最高記録・連続記録 … `FZ.max('<id>', '<項目>', 値)`
3. `data/apps.json` に1行足す（トップの一覧に出る）。
4. `data/unlocks.json` の `drops` にそのゲームの到達点を足し、同じ数だけ `sounds` に音源も足す。
5. 小さい画面（375×667 / 320×568）でもページがスクロールしないことを確かめる。

ドロップの判定・獲得演出・保存・到達点の帯は `core.js` がやるので、ゲーム側は報告するだけでよい。

## 音源を作る

```
python3 tools/make_sounds.py
```

- numpy だけで全部の WAV を合成する。22050Hz・モノラル・16bit。同じテンポのセットは全部同じ長さ（120: 4秒 / 180: 5.33秒 / 400: 2.4秒 / 1280: 3秒）。
- **既存の音は1バイトも変えない**。乱数を使う関数の順番や回数を変えると、後ろの音が変わるので注意。差し替えた古い関数も、乱数の並びを保つために呼ぶだけ残してある。
- 音の出だしは拍の格子の上に置く（120/180/400 は16分、1280 は1拍）。テストで確かめている。

## キャッシュ対策

GitHub Pages はファイルを約10分キャッシュするので、`core/` や `data/` を変えたら `core/core.js` の `V` と各 HTML の `?v=` を同じ数字で上げる（今は 10）。ずれているとテストが落ちる。

## 英語・日本語

- デフォルトは英語。右上の `EN / JA` で切り替え（その場で書き換わる）。選択はブラウザに保存（キー `fuzake-box-lang`。セーブコードには含めない）。
- JSON の文言は `{ "en": "...", "ja": "..." }` で書く（`FZ.t(値)` が今の言語を取り出す）。
- ページの固定文言は `const T = { en: {...}, ja: {...} }` に書き、要素に `data-i18n="キー"`（改行入りは `data-i18n-html`）を付けて `FZ.apply(T)` を呼ぶ。

## ローカルで動かす

パスがルート基準（`/core/...`）なので、リポジトリ直下でサーバーを立てる：

```
python3 -m http.server 8000
# → http://localhost:8000/
```

## テスト（TDD で運用する）

```
npm install        # 初回だけ
npm test           # 全部（276件）
npm run test:watch
```

- Jest ＋ jsdom。`tests/helpers/page.js` の `openPage('/apps/hanko/', {...})` で、リポジトリのページをそのままブラウザ代わりに開く。
  fetch・AudioContext・時計（`page.clock.ms`）・乱数（`opts.random`）・`confirm()`（既定で false）などは差し替えてある。
- `tests/helpers/wav.js` … WAV を読んで、音の出だしの時刻を拾う
- `tests/data.test.js` … データとファイルの整合性（音源の長さ・拍・ベースの割合・おすすめ・到達点の数・キャッシュ用バージョン・favicon など）
- `tests/core.test.js` … 保存・ドロップ・獲得演出・セーブコード・言語・到達点の帯
- `tests/top.test.js` … トップ（プロフィール・箱・アプリ一覧のページ送り・グルーヴ機・おすすめ・上限・演出・FEVER・セーブ）
- `tests/apps.test.js` … 各ゲームの基本の遊び方
- `tests/behaviors.test.js` … 遊び方のバリエーション（連続で間違える など）の記録
- 進め方：**先に失敗するテストを書く → 実装して通す → 整える**。直したバグにも、再発を防ぐテストを1つ足す。
- push と PR で GitHub Actions が `npm test` を回す（`.github/workflows/test.yml`）。
